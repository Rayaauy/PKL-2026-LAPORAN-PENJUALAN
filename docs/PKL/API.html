Request & Response

Successful Response (HTML)

Status: 200 OK or 302 Found (redirect)
Redirect with flash message:
  session('message') = "Product created successfully"
  session('alert') = "success"

Validation Error (HTML)

Status: 422 Unprocessable Entity
Response: Form with error messages
Fields: $errors['field_name'] = ["Error message"]
Input: Old form data re-filled

Authorization Error

Status: 403 Forbidden
User doesn't own resource or not authorized

Not Found

Status: 404 Not Found
Route or resource doesn't exist

Rate Limit

Status: 429 Too Many Requests
Wait before retrying

Create Transaction Example

Request

POST /transactions

Body (form):
  transaction_date: 2024-01-10
  notes: Sale from store
  items[0][product_id]: 5
  items[0][quantity]: 2
  items[1][product_id]: 12
  items[1][quantity]: 1

Response (success)

Status: 302 Found
Location: /transactions
Flash: "Transaction TRX-20240110-00001 created"

Database:
  INSERT transactions 
    (user_id, transaction_code, transaction_date, total_amount, notes)
  INSERT transaction_items (2 rows)

Response (validation error)

Status: 422 Unprocessable Entity
Form returned with:
  errors['items'] = ["At least one item required"]
  old form data re-filled

Middleware Stack

All Authenticated Routes

  • web — Session, CSRF tokens
  • auth — Check logged in
  • throttle:60,1 — Rate limit 60/minute

Admin Routes

  • web
  • auth
  • admin — Check is_admin = true
  • throttle:60,1

Data Scoping

All data automatically scoped to authenticated user. Queries include where('user_id', auth()->id())

  • User A cannot see User B's products
  • User A cannot see User B's transactions
  • User A cannot see User B's reports
  • Only admins can manage blog

See Architecture for request flow details.
