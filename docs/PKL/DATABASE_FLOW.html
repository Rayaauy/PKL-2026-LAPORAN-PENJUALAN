1️⃣ Data Flow: User Registration

INPUT User submits form: name, email, password
↓
VALIDATION • Email format valid
• Email not exists in DB
• Password min 8 chars & confirmed
↓
PROCESS • Hash password dengan bcrypt
• Set is_admin = false (default)
↓
INSERT INSERT INTO users (name, email, password, is_admin, created_at, updated_at)
VALUES ('John', 'john@mail.com', 'hashed_pwd', false, NOW(), NOW())
↓
OUTPUT ✓ User account created
✓ Redirect to login page
⚠️ Important: Password disimpan hashed, tidak bisa di-reverse. Setiap login, password yang di-submit di-hash dan dibandingkan dengan hash di database.

4️⃣ Data Flow: Create Transaction

Step 1: Input Transaksi Header

INPUT • Transaction Date: 2024-01-10
• Notes: Penjualan offline
↓
INSERT INSERT INTO transactions
(user_id, transaction_date, notes, created_at)
VALUES (1, '2024-01-10', 'Penjualan offline', NOW())

Generated transaction_code: TRX-20240110-00001
↓
RESULT Transaction ID: 15

Step 2: Add Transaction Items (Multiple)

ITEM 1 • Product: Laptop Dell (ID: 42)
• Quantity: 2
• Price from DB: 8500000
• Subtotal: 17000000
↓
INSERT INSERT INTO transaction_items
(transaction_id, product_id, product_name, price, quantity, subtotal)
VALUES (15, 42, 'Laptop Dell', 8500000, 2, 17000000)
↓
ITEM 2 • Product: Mouse Wireless (ID: 35)
• Quantity: 3
• Price from DB: 150000
• Subtotal: 450000
↓
INSERT INSERT INTO transaction_items
(transaction_id, product_id, product_name, price, quantity, subtotal)
VALUES (15, 35, 'Mouse Wireless', 150000, 3, 450000)
↓
CALCULATE TOTAL total_amount = 17000000 + 450000 = 17450000
↓
UPDATE UPDATE transactions
SET total_amount = 17450000
WHERE id = 15
↓
RESULT ✓ Transaction TRX-20240110-00001
✓ Total Rp 17.450.000
✓ 2 items recorded
💡 Catatan: Setiap transaksi item menyimpan snapshot product_name dan price pada saat transaksi. Jika nanti product price berubah, history transaksi tetap akurat.

🔒 Data Integrity & Constraints

PRIMARY KEY (PK)
• Setiap row unik
• Auto-increment (1, 2, 3...)
• Tidak bisa NULL
• Contoh: users.id, products.id
FOREIGN KEY (FK)
• Referensi ke tabel lain
• Menjaga relasi integrity
• ON DELETE CASCADE/RESTRICT
• Contoh: products.user_id → users.id
UNIQUE CONSTRAINT
• Nilai tidak boleh duplikat
• Contoh: users.email
• Contoh: transactions.transaction_code
• Cegah data duplikasi
NOT NULL / DEFAULT
• Field required / optional
• Default value otomatis
• Contoh: is_active DEFAULT true
• Contoh: stock DEFAULT 0
✓ Cascade Delete: Jika user dihapus, products, categories, transactions, dan semua relasi otomatis terhapus. Contoh: ON DELETE CASCADE

✓ Restrict Delete: Jika ada transaction_items mereferensi product, product tidak bisa dihapus. Harus hapus transaction items dulu. Contoh: ON DELETE RESTRICT

⚡ Query Optimization Tips

✓ Eager Load Relationships
// ❌ N+1 Problem (slow)
$products = Product::all();
foreach($products as $p) echo $p->category->name;

// ✓ Eager Load (fast)
$products = Product::with('category')->get();
✓ Use Select Specific Columns
// ❌ Ambil semua kolom
$users = User::all();

// ✓ Ambil kolom yang perlu
$users = User::select('id', 'name', 'email')->get();
✓ Add Database Indexes
// Foreign keys should be indexed
$table->index('user_id');
$table->index('category_id');
$table->index('transaction_id');
✓ Pagination for Large Lists
// Don't load all records
$products = Product::where('user_id', $userId)
->paginate(15);
